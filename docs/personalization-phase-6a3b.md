## Implemented screens

1. **Onboarding:** Czech goal → interests → experience → approximate session length → diagnostic → plan. Native radios and checkboxes; single-column choices; compact announced step text; previous navigation; server-action skip. The user-scoped session-storage draft recovers preference and question position on refresh without becoming authoritative storage.
2. **Result plan:** `/onboarding/plan` reloads the stored profile and actual progress on the server. It shows the goal, session length, actual published lesson/module/duration, a reason-code explanation, and lesson/curriculum links. Refresh is safe. It never displays a diagnostic score or rank.
3. **Learn:** one prominent “Doporučeno pro tebe” section uses the recommendation engine. A separate continuation link appears if an existing active lesson differs from the recommendation. The complete ordinary curriculum stays visible. Completed/unavailable recommendations have explicit fallback copy and a curriculum link.
4. **Existing users:** a restrained “Přizpůsobit učení” prompt is optional and dismissible. Dismissal is scoped to the user and browser; Settings remains an entry point. Existing missing/incomplete profiles keep access.
5. **Settings:** primary goal, multiple interests, experience, and session length edit the existing profile through the 6A.3A action. Saving preferences preserves diagnostic evidence. The failed-save defect is fixed by preventing the form’s native reset after the React action transition. Existing controlled local state retains attempted selections on network and validation errors; no optimistic profile write or global state was added. Retry and refresh preserve the successfully saved choices.
6. **Retake:** Settings opens the same question renderer in retake mode. The server replaces the diagnostic and the plan recomputes from stored evidence. The original personalization marker remains unchanged.
7. **Scaffolding:** recommendation-level guidance for guided/standard/compact is implemented in an optional “Jak si rozvrhnout učení” disclosure. It is reading guidance only; lesson screens are unchanged.
8. **Example context:** ETF/stock/portfolio/data context influences recommendation copy. No lesson examples have been rewritten. The existing renderer does not expose clean interchangeable examples or optional hints; lesson-level adaptations are deferred.
9. **Legacy recommendedStart:** no reads on the migrated Learn, onboarding, plan, or Settings surfaces. It remains in the schema, compatibility onboarding repository, demo seed, and the existing progress repository's completion-continuation logic. The learner-summary parameter name remains, but `loadLearner` now supplies the engine-selected module. No cleanup migration.
10. **Session presentation:** onboarding and Settings use approximate session length/tempo. The old daily-goal widget is no longer rendered on Learn. Existing gamification calculations and Progress presentation remain unchanged. Inactive legacy onboarding components remain for compatibility and are not imported by these routes.

## Authority and resilience

11. The server passes only diagnostic question IDs, prompts, and option IDs/labels to the client. No answer key or stored evidence crosses this onboarding boundary. Clients submit preference inputs and versioned answer IDs; strict server schemas reject score, XP, completion, entitlement, capital, recommendation, and scaffold fields. Action/session/ownership boundaries, first-completion semantics, and idempotent initial upserts are unchanged. Local drafts validate shape before restoration. Busy states prevent accidental resubmission; failed saves retain inputs and offer retry. Generic Czech page-load recovery uses the existing app error boundary.

No edits to financial lesson content, rewards (60 XP; 420 XP and seven Foundations for Lab; 5,000 Kč unlock grant), trading, accounting, market providers, charts, fundamentals, ETF analytics, or Backtesting. No new schema changes beyond preserved 6A.3A. No live providers or AI API calls.
